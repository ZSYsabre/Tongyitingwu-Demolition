Agent contracts

通义听悟的 Agent 组织方式

官方页面没有声称其内部使用多 Agent。本文把可见功能重构为一组“功能等价 Agent 契约”：已确认的是能力和输入输出，Agent 分工为合理推断/建议设计。

合理推断 “Agent”是用于逆向建模的责任单元，不等于官方公开的后台服务名。

3·详细 Agent 契约

A0 · 任务编排 Agent

契约项内容
目标将 JobSpec 转成有依赖的执行图，控制实时和离线两种时序。
先决条件媒体可读；语言/格式/采样率/时长/配额校验通过。
不变式用户未请求的付费/分享/删除操作不自动执行；每个阶段可观测、可重试。
失败保留已完成的中间结果，区分“转写失败”与“总结失败”。

A2 · 语音转写 Agent

契约项内容
输入PCM/标准化音轨、语言模式、专有词、实时/离线模式。
输出带起止时间的 utterance 序列，可附加声音事件。
质量要求断句稳定；专有词命中；不确定片段保留低置信标记，不用常识补齐。
编辑传播用户编辑后产生新版本，触发译文及相关摘要的可控刷新。

A5/A6 · 结构化理解与会议洞察

约束要求
事实性只用转写中的信息；不将推测写成已决定事实。
待办尽量抽取责任人、动作、截止时间、依赖；缺失时标记“未明确”。
问答区分显性提问与隐性问题；回答不得超出对话。
证据每个章节、关键结论、待办、问答附时间范围和 utterance id。
场景会议/访谈/课程/演讲仅用于选择输出结构，不更改原事实。

A7 · PPT 理解 Agent

  • 只在视频来源且检测到演示页时运行。
  • 对相邻帧去重，保留清晰主帧，关联页面起止时间。
  • 总结的是“这一页与其讲解”，不只是 OCR 文字。
  • 未看清的小字标记不确定，不献测。

A10 · 资产与分发 Agent

  • 导出是明确的用户触发动作，选择内容、格式、目标位置。
  • 公开分享前显示权限，“允许创建副本”是独立开关。
  • 阿里云盘导出与本地下载是两个独立交付器，失败可分别重试。

4·跨 Agent 不变式

时间线为主键文字、章节、PPT、待办、笔记都能回到时间段。
人工更正优先用户编辑后的原文和发言人名不被后台自动结果覆盖。
派生内容可再生原文变更后，译文和摘要能按版本重算。
无证据不确认不可验证的责任人、日期、数字统一标注为未明确。
